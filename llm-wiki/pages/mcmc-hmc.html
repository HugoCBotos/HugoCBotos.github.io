10. MCMC and Hamiltonian Monte Carlo

🎯 In one sentence

Instead of approximating the posterior with a simple distribution (like a Gaussian), MCMC methods generate samples directly from the true posterior by exploring the weight space using a guided random walk. They are the "gold standard" — but too expensive for modern neural networks.

This page is conceptual. HMC is rarely used for full-size neural networks in practice. But understanding it is essential because it's the reference point against which all other methods are judged. If a cheaper method disagrees with HMC, the cheaper method is wrong.

The Big Idea of MCMC

Markov Chain Monte Carlo (MCMC) is a class of algorithms for sampling from a probability distribution that we can't compute directly. The idea:

  1. Start at some point in weight space.
  2. Propose a new point (some random modification to the weights).
  3. Accept or reject the proposal based on how much it improves the posterior probability.
  4. Repeat. The sequence of accepted points forms a "Markov chain" whose distribution converges to the true posterior.

After enough steps, the samples w1, w2, ..., wT are approximately drawn from p(w|D). We can use them to approximate the predictive distribution:

Predictive distribution via MCMC
$$p(y^* \mid x^*, D) \approx \frac{1}{T} \sum_{t=1}^{T} p(y^* \mid x^*, w_t)$$

The Problem With Simple MCMC

The simplest MCMC method is random-walk Metropolis-Hastings. It uses two different sources of randomness, and confusing them is common:

Algorithm (step by step):

  1. Start at some point w in weight space.
  2. Propose a new point: w' = w + noise.
    ↳ The noise is a random vector (e.g., Gaussian). This is randomness source #1: which direction to try.
  3. Compute ratio: r = p(w'|D) / p(w|D).
    ↳ This tells us: is the new point more probable (r > 1) or less probable (r < 1) than the current one?
  4. Decide:
    • If r ≥ 1, always accept: move to w'.
    • If r < 1, accept with probability r.
      ↳ To do this, draw a uniform random number u ∈ [0, 1]. Accept if r > u.
      ↳ This u is randomness source #2: whether to accept a bad proposal.

Let's be very explicit about the two different "random"s:

Randomness #1: Proposal noiseRandomness #2: Acceptance coin-flip
What it isA random vector added to the current weightsA single random number between 0 and 1
PurposeDecides where to try nextDecides whether to go to a worse point
Why neededOtherwise you'd always stay where you areOccasionally accepting worse points lets the chain explore the whole distribution
Codenoise = torch.randn(d) * step_sizeu = torch.rand(1).item()

Why It Fails in High Dimensions

In 1 dimension, random-walk works fine: about half the proposals go uphill (higher probability) and half go downhill. The chain explores the distribution.

Think of this: You're standing in a dark room and want to find all the furniture. You take a random step. In 1D (a hallway), a random step goes either left or right — a 50% chance of going the right way. In 1 million dimensions (a hangar), a random step goes in 1 of 106 directions. Almost every direction is wrong — you'll just stumble into a wall (low probability region) and get rejected.

Mathematically, the acceptance rate drops rapidly with dimension because:

  • The probability of a random direction being "good" scales like d−1/2 (extremely small for large d).
  • To keep acceptance rate reasonable, the step size must shrink like d−1/2, making exploration painfully slow.
  • The chain becomes "stuck" — consecutive samples are nearly identical (high autocorrelation).

This is why random-walk MCMC is useless for neural networks (millions of parameters). HMC fixes this by replacing the random proposal with a gradient-guided proposal — you use the slope of the posterior to decide which direction to go, rather than guessing randomly.

Hamiltonian Monte Carlo (HMC)

HMC solves this by using gradient information to propose intelligent moves. It's inspired by Hamiltonian mechanics.

Analogy: Imagine a frictionless puck sliding on a hilly landscape. The landscape is the negative log-posterior (high hills = low probability). Give the puck a random kick (momentum), let it roll according to physics, and record where it goes. The puck explores the landscape efficiently because it follows the terrain — rolling downhill (toward high probability) and coasting uphill (away from high probability) with momentum.

The mathematics:

HMC Dynamics
$$\text{Hamiltonian: } H(w, p) = -\log p(w \mid D) + \frac{1}{2} p^T M^{-1} p$$ $$\text{Potential energy: } U(w) = -\log p(w \mid D)$$ $$\text{Kinetic energy: } K(p) = \frac{1}{2} p^T M^{-1} p$$

The algorithm alternates between:

  1. Sample momentum p ~ N(0, M) (random kick).
  2. Simulate Hamiltonian dynamics for L steps using the leapfrog integrator (follow the terrain using gradient information).
  3. Accept/reject the final (w, p) based on energy conservation (acceptance ≈ 1 with accurate integration).

HMC in PyTorch (for a Small Model)

Here's a minimal HMC implementation for a tiny neural network. This is not for production — use Pyro's NUTS instead — but it shows the core logic:

import torch
import torch.nn as nn
import torch.nn.functional as F

# ---------- Step 1: Define the log-posterior ----------
def log_posterior(model, x, y, prior_std=1.0):
    """Compute log p(w|D) = log p(D|w) + log p(w) + constant"""
    pred = model(x)
    log_lik = -F.cross_entropy(pred, y)
    log_prior = 0.0
    for param in model.parameters():
        log_prior += -0.5 * (param**2 / prior_std**2).sum()
    return log_lik + log_prior

# ---------- Step 2: HMC sampler (with Metropolis acceptance) ----------
def hmc_sample(model, x, y, step_size=0.01, L=20, num_samples=100, prior_std=1.0):
    """
    Hamiltonian Monte Carlo.
    
    The algorithm:
    1. Start at current position w.
    2. Sample random momentum p ~ N(0, I).
    3. Simulate Hamiltonian dynamics for L leapfrog steps
       (uses gradient of the posterior to guide the proposal).
    4. Accept/reject based on energy conservation.
    
    In practice: use Pyro's NUTS sampler instead.
    """
    samples = []
    current_w = [p.data.clone() for p in model.parameters()]
    
    for _ in range(num_samples * 2):  # extra for burn-in
        # --- Copy current weights ---
        w = [p.clone() for p in current_w]
        
        # --- Sample momentum p ~ N(0, I) ---
        p = [torch.randn_like(w_i) for w_i in w]
        
        # Compute current Hamiltonian: H(w, p) = U(w) + K(p)
        # U(w) = -log p(w|D),  K(p) = ½ p·p
        for i, param in enumerate(model.parameters()):
            param.data = w[i]
        U_current = -log_posterior(model, x, y, prior_std)
        K_current = 0.5 * sum((p_i**2).sum() for p_i in p)
        H_current = U_current + K_current
        
        # --- Leapfrog integration (L steps) ---
        for _ in range(L):
            # Half-step momentum: p -= ε/2 * ∇U(w)
            for i, param in enumerate(model.parameters()):
                param.data = w[i]
            log_p = log_posterior(model, x, y, prior_std)
            log_p.backward()
            for i, param in enumerate(model.parameters()):
                p[i] -= 0.5 * step_size * (-param.grad)  # ∇U = -∇log_p
            
            # Full-step position: w += ε * p
            for i in range(len(w)):
                w[i] = w[i] + step_size * p[i]
                model.parameters()[i].data = w[i]
                model.parameters()[i].grad = None  # clear gradients
            
            # Another half-step momentum: p -= ε/2 * ∇U(w_new)
            log_p = log_posterior(model, x, y, prior_std)
            log_p.backward()
            for i, param in enumerate(model.parameters()):
                p[i] -= 0.5 * step_size * (-param.grad)
                param.grad = None
        
        # --- Compute Hamiltonian at proposal ---
        U_proposed = -log_posterior(model, x, y, prior_std)
        K_proposed = 0.5 * sum((p_i**2).sum() for p_i in p)
        H_proposed = U_proposed + K_proposed
        
        # --- Metropolis accept/reject based on energy difference ---
        delta_H = H_proposed - H_current
        if delta_H < 0 or torch.rand(1).item() < torch.exp(-delta_H):
            current_w = [w_i.clone() for w_i in w]  # accept
        
        # Store current sample (accepted or not)
        for i, param in enumerate(model.parameters()):
            param.data = current_w[i]
        samples.append([w_i.clone() for w_i in current_w])
    
    return samples[num_samples:]  # discard burn-in
⚠️ This code is for illustration only! In practice, use Pyro's NUTS sampler or TensorFlow Probability's HMC. They handle step size adaptation, mass matrix estimation, and convergence diagnostics automatically. The code above uses a fixed step size and diagonal mass matrix (M = I), which will perform poorly without careful tuning.
✅ Note on the accept/reject step: The Metropolis-Hastings accept/reject step (checking exp(-ΔH) against a random number) is essential for valid posterior sampling. Without it, the trajectory is just gradient-guided optimization — it would not produce samples from the true posterior. Even with an accurate leapfrog integrator, numerical errors accumulate, making the correction necessary. The code above correctly implements this step.

Why HMC is the Gold Standard

  • Asymptotically exact: As the number of samples → ∞, the distribution of samples converges to the true posterior. No approximation error (unlike VI or Laplace).
  • Gradient-guided: Uses the geometry of the posterior to propose efficient moves, unlike random-walk Metropolis.
  • Reference for evaluation: When Izmailov et al. (2021) wanted to know how bad VI and Laplace approximations are, they compared them to HMC.

Why It's Rarely Used for Modern Networks

RequirementHMCPractical Implication
Gradients of full log-posterior Needs gradient of all data per step Can't use mini-batches (stochastic gradients break detailed balance)
Number of gradient evaluations L × (N_data) per sample 100-1000× more computation than standard training
Autocorrelation Needs many samples for accurate estimates Need to run long chains (10K+ samples)
Tuning Step size, trajectory length, mass matrix Requires careful adaptation (NUTS automates this but is still expensive)

Practical verdict: HMC is feasible for models with up to ~10⁴ parameters. Beyond that, use VI, MC Dropout, or Laplace. But always validate your approximation against HMC on a smaller version of your problem if possible.
